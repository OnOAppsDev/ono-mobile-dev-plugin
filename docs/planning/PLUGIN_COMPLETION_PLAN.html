1. Architecture

Every lifecycle stage runs one shared role agent plus one shared lifecycle methodology, against exactly one platform lane resolved from the confirmed platform. The agent and the methodology are platform-independent; the lane is the only source of platform content.

Exactly one platform lane is ever loaded. No other platform's lane or standards may be loaded in the same invocation.

6. Standing constraints

  • Four platforms only — React Native, React, iOS, Android. TV is a device_type context signal inside a platform, never a new platform value.
  • Standards are frozen in content. IDs are never renumbered or re-homed; rules, severity, applicability and paths do not move. Reference-only edits replacing retired agent names with role names are the sole exception, and were applied once during the cleanup.
  • Repository knowledge belongs to ono-project-inspector. This plugin may inspect a repository for the duration of one run; it never writes CLAUDE.md, AUDIT.md, docs/project/**, audits/** or .ono/**, and never becomes the authority on what a repository is.
  • Validation is a capability, not a workflow step. node scripts/check.ts --strict runs from a shell with no network and no dependencies. No command invokes it; it must never become mandatory for users of the plugin.
  • Approval stays human. The plugin never regenerates an approved document, never edits upstream requirements, and never revokes approval.
  • Deterministic checks cover the deterministic layer only. Model-driven behaviour — detection, file attribution, document quality, implementation correctness, review findings — is out of their reach by design and is verified by review or claude plugin eval.
