1. Architecture

Every lifecycle stage runs one shared role agent plus one shared lifecycle methodology, against exactly one platform lane resolved from the confirmed platform. The agent and the methodology are platform-independent; the lane is the only source of platform content.

Exactly one platform lane is ever loaded. No other platform's lane or standards may be loaded in the same invocation.

3. Readiness matrix

Ready — every component on that platform's command → role agent → shared methodology → lane path is authored and reachable. Blocked — the path reaches authored components, but the standards carry no rules for that context, so the lane can discover and avoid regression without citing guidance. Gate B — End-to-end validation

A real Claude-driven claude plugin eval run of the complete workflow — /analyze-feature → /dev-design-start → /dev-feature-start → /implement-task → /review-code → /fix-review-comments → /create-dev-qa-notes → /prepare-mobile-release — on a real repository.

  • All four platforms — react-native, ios, android, react.
  • Both device types where applicable — mobile and tv on iOS, Android and React. React Native is mobile-only; its tv path is validated by confirming the hard stop fires and never falls through.
  • Gate A first for the TV paths: an Apple TV or Android TV run before ATV-001 / ANDROID-003 can only demonstrate discovery, not guidance.
What check.ts cannot prove, and never will

The deterministic suite validates the deterministic layer only. These are out of its reach by design and are the reason Gate B exists as separate work:

  • Platform and device_type detection, and per-file attribution — specified in prose, executed by Claude.
  • Design-document content quality, implementation correctness, review findings, QA prose.
  • That any command, skill or agent behaves correctly when Claude actually runs it.
  • That a readiness or approval gate, once present, actually stops or degrades correctly — gate text is prose.
  • Any TV behaviour at all. The harness deliberately carries no TV fixture, because no helper or hook reads device_type — a TV fixture would exercise no deterministic branch. TV coverage is therefore a claude plugin eval obligation, not a harness one: still required, simply not provable here.

Gate C — Release readiness

  • Documentation matches actual behaviour — README.md, CHANGELOG.md and every pipeline/routing table describe the shared-lifecycle architecture as it actually routes.
  • No stale references to deleted legacy agents outside CHANGELOG.md, dated records under docs/planning/, test fixtures and git history.
  • ENG-006 decided — dd-complexity-assessment is either wired to a real effect or removed. No live-but-inert component ships.
  • Plugin version intentionally finalized — plugin.json is bumped as a deliberate act. It has been held un-bumped on purpose throughout; the bump is separate work, not a side effect of any ticket.
  • [Unreleased] cut — the accumulated CHANGELOG entries are moved under the finalized version with its date.
  • Final regression green — node scripts/check.ts --strict passes with zero failures and zero skipped, and git diff --check is clean.
  • Explicit sign-off — per §8.

8. Definition of Done

A platform — including its TV context, where it has one — is supported only when all ten hold. The plugin is complete when all four platforms are supported and Gates A, B and C have passed.

#Condition
1Platform standards complete and enforceable. No file left Not yet authored; no re-inheriting of React-Native-flavoured shared rules; every rule carries a citable stable ID. For a TV context, the TV subject areas are authored — focus, remote input, playback, lifecycle, TV signing and packaging.
2Platform lanes complete. All three lanes — *-dev-planning, *-feature-implementation, *-code-review — are authored, carry only platform-specific content, and branch correctly on device_type.
3Shared role agents resolve correctly to the lanes. feature-architect, feature-implementer, code-reviewer and performance-reviewer each resolve to a real, non-placeholder lane for that platform, loading exactly one; the agents and the three shared methodologies stay platform-neutral and carry no platform content.
4Context propagates end to end. Confirmed platform and device_type are carried in frontmatter from /analyze-feature's human confirmation through every later stage, are never re-detected downstream, and are never emitted as mixed. Templates and metadata carry both, and the per-platform review, QA and release sections render.
5Approval and readiness gates never fall back silently. Each gate's declared semantics hold — /implement-task hard-stops, /review-code excludes and declares, /fix-review-comments skips and reports, /prepare-mobile-release records unverifiable as a no-go. A TV target is never handled as mobile without the TV context applied, and no gate degrades into another platform's lane.
6Representative deterministic coverage exists where it is possible. The document-chain fixtures cover the mobile path, and node scripts/check.ts --strict is green with nothing skipped. No TV fixture is expected — no deterministic branch reads device_type, so one would prove nothing.
7Real Claude-driven end-to-end validation where the harness cannot prove behaviour. Gate B has run for that platform, covering both device types where applicable. This is the only evidence that detection, attribution, gate behaviour and output quality actually work.

9Release and version state consistent. plugin.json is at its intended finalized version and [Unreleased] has been cut to it.

9. Standing constraints

  • Four platforms only — React Native, React, iOS, Android. TV is a device_type context signal inside a platform, never a new platform value.
  • Standards are frozen in content. IDs are never renumbered or re-homed; rules, severity, applicability and paths do not move. Reference-only edits replacing retired agent names with role names are the sole exception, and were applied once during the cleanup.
  • Repository knowledge belongs to ono-project-inspector. This plugin may inspect a repository for the duration of one run; it never writes CLAUDE.md, AUDIT.md, docs/project/**, audits/** or .ono/**, and never becomes the authority on what a repository is.
  • Validation is a capability, not a workflow step. node scripts/check.ts --strict runs from a shell with no network and no dependencies. No command invokes it; it must never become mandatory for users of the plugin.
  • Approval stays human. The plugin never regenerates an approved document, never edits upstream requirements, and never revokes approval.
  • Deterministic checks cover the deterministic layer only. Model-driven behaviour — detection, file attribution, document quality, implementation correctness, review findings — is out of their reach by design and is verified by review or claude plugin eval.
