0. Architecture Decision (source of truth)

The plugin architecture is technology-based. There are four platforms only: React Native, React, iOS, Android. No separate tvOS or Android TV platform families are created. TV form-factor behavior (focus/remote/D-pad navigation, 10-foot UI, media playback, TV lifecycle, TV signing/packaging) lives inside the existing platform's Skills, Agents, and Standards, activated by a mobile-vs-TV context signal passed to those Skills/Agents when needed — a context signal, not a new platform value.

7. Definition of Done (per team)

A team's platform (including its TV variant, where applicable) is supported only when all hold:

  • Standards complete and enforceable (no "Not yet authored"), not re-inheriting RN-flavored shared rules, and — for Apple TV / Android TV / Smart TV — including TV-context sections (focus/remote/playback/lifecycle/TV signing/packaging).
  • Skills (dev-planning, feature-implementation, code-review) authored and branch correctly on the mobile-vs-TV context.
  • Agents (architect, feature-developer, code-reviewer, performance-reviewer) authored, citing the platform's standards, TV-context aware.
  • Command routing resolves the platform to real (non-placeholder) skills/agents and passes the mobile-vs-TV context through every stage.
  • Templates & metadata carry the platform and mobile-vs-TV context end to end; per-platform review/QA/release sections render.
  • Approval gates & error handling enforced; no silent fallback (a TV target is never handled as mobile without the TV context applied).
  • Representative fixtures (a mobile and a TV variant) exist under the SHARED-005 harness.
  • End-to-end dry run passes in CI for both the mobile and TV variant.
  • Documentation (README/CHANGELOG/pipeline tables) matches reality.
  • Owner sign-off — platform owner confirms the mobile bar is met; for Apple TV, Noam Haba confirms the TV context is genuinely applied; for Android TV, Guy Gur Arie; for Smart TV, Boris Molotsky.
