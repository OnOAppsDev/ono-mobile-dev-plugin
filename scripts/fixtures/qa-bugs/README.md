# QA bug fixture — one bug per lifecycle state

A real QA repository (`acme-qa/`), generated by ono-plugin-qa's own helper
(`scripts/qa-ledger.mjs`, the code merged on its `origin/main` as v0.8.0) with
`QA_LEDGER_NOW` pinned per step, so every record hash and every `bugs/<id>/bug.md`
is exactly what QA writes. Used by `scripts/bug-intake.test.ts`. Never edit by hand —
a hand edit breaks the record hashes the reader re-verifies.

| Bug | QA state | Built by |
|---|---|---|
| `BUG-41` | `new` | standalone `bug report` |
| `BUG-42` | `verification_blocked` | `bug verify --outcome blocked` |
| `BUG-43` | `assigned` | `bug verify --outcome reproduced`; `--external-ref PAY-1182 --related-scope feature:checkout` |
| `BUG-44` | `reopened` | reproduced → `build add atv-202 --fixes bug:BUG-44` → smoke passed → `bug retest --outcome fail` (notes + evidence) |
| `BUG-45` | `closed_verified` | reproduced → `build add atv-203 --fixes` → smoke passed → `bug retest --outcome pass` |
| `BUG-46` | `fix_delivered` | reproduced → `build add and-202 --fixes bug:BUG-46` |

`feature:checkout` carries a recorded Dev handoff (`scope event --op set --field dev_handoff`,
Dev feature `checkout-coupons`), so `BUG-43`'s `related_feature` resolves from QA's record.

The repository was a git root when generated (the helper requires one); `.git` is not
committed. QA's own `validate` passed on the result.
